# Git и SVN

## 1. Почему в Git ветвление дешёвое, а в SVN дорогое?

В Git ветка это просто файл с хешем коммита, на который она указывает, 41 байт. Создаётся она локально и мгновенно, сервер для этого не нужен. Переключение между ветками меняет только те файлы, которые отличаются.

В SVN ветка это копия каталога (обычно в /branches), которую делают командой svn copy на сервере. Сам сервер копирует дёшево, но для этого нужна сеть, ветка сразу видна всем, а чтобы на неё переключиться, приходится заново выкачивать рабочую копию. Дороже всего обходится слияние: до версии 1.5 SVN вообще не запоминал, что уже было влито, и это приходилось отслеживать вручную.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нельзя. История хранится только на центральном сервере, а у меня на компьютере лежит лишь рабочая копия последней скачанной версии. Коммит в SVN означает сразу отправить изменения на сервер, локального коммита там нет. Без сети можно только править файлы, смотреть diff с последней скачанной версией и откатывать свои правки.

В Git вся история лежит локально, поэтому коммиты, ветки и git log работают без сети, а на сервер всё уходит потом через push.

## 3. Когда SVN до сих пор может быть лучше Git?

- Много больших бинарных файлов: игровые ресурсы, видео, CAD-чертежи. В SVN можно выкачать одну папку и только последнюю версию, а Git тянет всю историю. Git LFS частично решает эту проблему, но настраивать его сложнее.
- Файлы, которые нельзя слить, например .psd или .docx. В SVN есть блокировки (svn lock): пока один человек редактирует файл, остальные его не трогают.
- Нужны права на отдельные папки внутри одного репозитория. В SVN это настраивается на сервере, в Git для этого обычно разбивают проект на несколько репозиториев.
- Старые проекты в банках и госсекторе, где на SVN завязаны сборка и регламенты и переезд стоит дороже, чем выгода от него.
